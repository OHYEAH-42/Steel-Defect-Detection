## 1. 项目背景、问题定义与目标

### 1.1 背景与问题

钢材表面可能出现裂纹、划痕、夹杂等不同类型的缺陷。人工观察与分类存在重复性劳动，因此本项目探索利用卷积神经网络对**已经含有缺陷的图像**进行六类别分类，并通过软件原型辅助呈现识别与实验分析结果。

本项目使用公开的 **NEU-CLS** 数据集，不具备真实生产线、工业相机或企业数据。NEU-CLS 原始说明包含六类、共 1,800 张灰度图像，每类 300 张，原始大小 200×200；实际下载文件须再次核验。

### 1.2 核心问题

- **RQ1：** ImageNet 预训练的 ResNet18 能否完成 NEU-CLS 六类已知缺陷分类？各类别表现如何？
- **RQ2：** 在固定数据划分和评价流程下，从“冻结特征提取层”到“部分层微调”的迭代，会带来怎样的性能及训练成本变化？
- **可选 RQ3：** 与简单 CNN 或随机初始化 ResNet18 相比，迁移学习方案有哪些差异？仅在扩展对比实验完成后回答。

### 1.3 项目目标

1. 建立可复现的数据读取、核查、划分和预处理流程。
2. 完成 ResNet18 迁移学习训练、验证、保存和独立测试。
3. 交付可本地运行的 Streamlit 单图分类原型。
4. 完成至少一轮**有依据、有记录**的模型训练策略迭代（最终课程交付目标，不阻塞首版 MVP）。
5. 提交可核验的实验结果、工程文档与课程报告。

### 1.4 任务边界

- **输入：** 单张钢材表面图像，预期属于六种已知缺陷之一。
- **输出：** 六类中的预测标签、六类模型输出概率及必要的边界说明。
- **不支持：** 正常/异常识别、合格/不合格判定、未知缺陷识别、缺陷定位或分割、工业实时检测。
- **解释约束：** Softmax 概率是模型输出，不等于经过校准的真实正确率或质量合格概率；对超出训练分布的图片不能保证结果可靠。

## 3. 数据工程需求及验收

### 3.1 数据来源与版本

记录原始数据源地址、下载日期、原始归档文件名称、版本或校验值、类别名称及使用/再分发约束。只使用分类图像 NEU-CLS；数据授权条款如未能核实，不擅自将整套原始数据重新公开发布。

固定六类映射并用于训练、评价和推理，例如：`Cr`（Crazing）、`In`（Inclusion）、`Pa`（Patches）、`PS`（Pitted Surface）、`RS`（Rolled-in Scale）、`Sc`（Scratches）。具体数字标签顺序须在项目配置中唯一确定，不允许依赖不稳定的目录遍历顺序。

### 3.2 数据探索和质量检查

- 核对实际样本总数、每类数量、文件格式、像素尺寸、颜色通道和可读取性。
- 展示每类代表性图像、类别数量图；统计并解释像素均值/标准差或灰度直方图。
- 检查损坏文件、完全重复图片；对疑似近重复图像进行记录和人工复核，特别注意跨划分泄漏风险。
- 如果检查发现样本异常，保留清理前后数量和处理理由，不为提升指标而随意删除难例。

### 3.3 数据集划分

默认采用**分层 70%/15%/15%**，并固定随机种子和清单。若 1,800 张均通过检查且各类仍为 300 张，则为：

| 数据集 | 总数 | 每类数量 | 用途 |
|---|---:|---:|---|
| 训练集 | 1,260 | 210 | 参数学习和随机增强 |
| 验证集 | 270 | 45 | 模型选择、调参、提前停止 |
| 测试集 | 270 | 45 | 最终一次性独立评价 |

要求：先核查重复/近重复，再拆分；保存 `train/val/test` 样本列表；不同版本实验使用**同一划分**；训练集和验证/测试集无文件交叉。若清理导致数量变化，按实际清理后的数据生成统计，不强行凑齐上述数值。测试集不得参与调参与模型选择。

### 3.4 预处理和增强

- 统一将图像调整为 `224×224`；ResNet18 输入转为 3 通道，并使用相应 ImageNet 预训练权重的归一化参数。
- 验证、测试与 Web 推理采用对应的确定性预处理；不使用随机增强。
- 训练集可采用适度旋转或翻转，须确认不改变缺陷类别语义，并保存增强配置及示例。
- 如要研究增强作用，留到 MVP 完成后做 O2 对比，避免在首轮训练中同时改变多个变量。

**数据工程验收证据：** 数据来源说明、统计表、样例图、质量检查记录、灰度分布图、固定划分清单、变换配置与增强示例。

## 4. 模型训练、迭代与评估要求

### 4.1 首版 MVP 模型 C0

| 配置项 | 初始方案（可根据验证集调整并留痕） |
|---|---|
| 网络 | `torchvision` ResNet18，ImageNet 预训练权重 |
| 训练策略 | 冻结主干参数，替换末端全连接层为六分类 |
| 输入 | 224×224、3 通道、与所用权重一致的归一化 |
| Batch Size | 32；显存不足时改 16 并记录 |
| 优化器/损失 | Adam / CrossEntropyLoss |
| 初始学习率 | 1e-3（训练分类层） |
| 最大 Epoch | 15；早停耐心值可先设 5 |
| 模型选择 | 验证集 Macro-F1 最优 |
| 计算设备 | Windows + NVIDIA RTX 4060 8GB；PyTorch CUDA |

训练时保留每轮的训练/验证损失、准确率、验证 Macro-F1、耗时和最佳 Epoch；将最佳模型权重及配置、类别映射一起保存。初始参数是计划值，不是必须达到的最优值。

### 4.2 后续迭代模型 C1

C0 MVP 完成后，在 C0 最优权重基础上，尝试解冻 ResNet18 的最后一个残差模块 `layer4` 与 `fc`，降低学习率（例如 `1e-4`）继续训练，形成 C1。记录额外训练轮数、耗时、验证集结果和变化原因。**因为 C1 在 C0 基础上继续训练，其与 C0 的差异还包含额外训练预算；不能把全部效果变化简单归因于“解冻层”。** 如果课程需要严格消融，再追加控制训练预算的独立对照。

C1 不要求必然优于 C0；即使指标下降，也须依据训练/验证曲线分析原因。模型最终选择以验证集结果为准。

### 4.3 统一评估

- 必备：测试集 Accuracy、Macro-Precision、Macro-Recall、Macro-F1、六类逐类 Precision/Recall/F1、混淆矩阵。
- 必备：训练损失和验证损失曲线；至少记录验证集 Accuracy 与 Macro-F1 的变化。
- 最终课程交付：C0/C1 指标对比、训练成本说明、至少 5 个真实误分类案例（若测试集错误不足 5 个，应如实给出全部错误并说明）。
- 禁止用测试集反复调参、反复选择模型或只展示效果好的图片。
- 不设置虚构的硬性精度门槛：`Macro-F1 ≥ 0.85` 可作为**努力目标**，不作为 MVP 是否通过的唯一标准。评价以真实、可复现结果为准。

## 5. Web 功能及验收场景

### 5.1 单张图片分类（M0）

用户通过 Streamlit 上传一张 JPEG/PNG 图像；界面显示原图预览，调用已训练 ResNet18，显示六类中的预测标签及六类输出概率，并显示“仅支持六类已知缺陷分类，不等于质量合格判定”的说明。

**验收：** 使用至少 3 张有效图像逐一演示，均能显示预览、有效类别标签和六个数值概率；概率均在 `[0,1]`，总和在浮点容差内约等于 1（例如误差不超过 `1e-4`）。预测标签应为概率最大的一类。演示样本不能替代独立测试集评价。

### 5.2 输入异常和可恢复性（M0）

对不支持格式、损坏/无法解码文件、未加载模型等情况给出清楚提示；不应使整套应用不可恢复地崩溃。限制单张上传大小（初拟 10MB，可按实际调整）并在 README 说明。

**验收：** 分别测试有效图片、不支持格式、损坏图片、模型文件缺失四种情形；记录测试结果与截图。可通过 Streamlit 上传格式限制和后端解码校验共同保证。

### 5.3 实验结果呈现（M0）

展示当前模型的指标摘要、混淆矩阵及训练曲线，可采用独立“实验分析”页面，也可在单页的第二部分呈现。展示的数据须来自真实评估输出，不允许将假设指标写成实际结果。

**验收：** 至少能查看测试集 Accuracy、Macro-F1、混淆矩阵和一组训练曲线；结果与评价脚本导出文件一致。

- PDF 示例共 2 页，其中 2022 年日期、姓名、空泛章节和示例图表是**模板占位**，不能据此推断最终报告只有两页。

**模板未明确的事项：** 报告最低/最高页数、字数、答辩时长、必须提交的文件格式、是否强制双语全文、模型数量要求。不得自行将建议误写为教师硬性规定。

### 9.2 推荐的正式报告结构（与考核权重对应）

| 建议章节 | 重点内容 | 主要关联的评分维度 | 应预留的证据 |
|---|---|---|---|
| 标题、作者信息、中文摘要、Abstract、关键词 | 说明研究任务、方法、实际结果和结论 | 报告与反思 | 真实完成情况、主要指标 |
| I. 引言与问题定义 | 钢材表面缺陷分类背景、具体任务、RQ1/RQ2、适用范围 | 问题定义 10% | 任务流程图、相关文献 |
| II. 数据集与数据工程 | NEU-CLS 来源、EDA、质量检查、固定划分、防泄漏、增强 | 数据工程 15% | 类别统计、样本图、灰度直方图、划分表 |
| III. 模型与实验方法 | ResNet18 结构、预训练、C0 策略、训练配置、指标定义 | 模型迭代 15% | 方法示意、参数表 |
| IV. 实验结果与模型迭代 | C0 实验、C1 微调、训练曲线、验证/测试指标、混淆矩阵、错误案例 | 模型迭代 15%；报告与反思 35% | 指标表、训练曲线、错误样本 |
| V. 系统设计与工程化交付 | 模块设计、Streamlit 识别流程、测试用例、复现过程 | 工程化交付 25% | 结构图、交互截图、测试记录、README |
| VI. 讨论与反思 | 问题与困难、改进依据、负面结果、局限、团队协作和 AI 使用情况（如适用） | 报告与反思 35% | 实验记录、决策日志、问题闭环 |
| VII. 结论与展望 | 总结任务完成情况、结论的适用范围和可选后续方向 | 报告与反思 | 结论与证据对应关系 |
| 参考文献（及必要的附录） | 数据集/架构/框架出处，补充参数与复现说明 | 学术规范 | 可查证的文献、代码信息 |

> 上述章节名称和篇幅分配由团队自行设计，**不是**报告模板中规定的章节内容。建议所有关键图、表在正文中有文字解释，不只是堆叠截图。

### 9.3 写作质量与反思验收

1. 区分实际完成与计划/可选事项，不夸大系统具备工业质检能力。
2. 关键结论必须有实际实验图表或日志支持；不得编造准确率、训练耗时或“提升百分比”。
3. 如实记录失败、退化、困难或设计取舍；例如 C1 未提升时，应保留结果并解释，不能隐瞒。
4. 阐述为何采用 ResNet18、冻结/微调策略，以及为何不做正常/异常检测和 YOLO。
5. 说明小样本、无正常样本、未知类别及真实工业场景分布偏移等局限。
6. 如实际使用 AI 辅助代码与报告，说明使用环节、人工审核方式与对最终结论的责任。
7. 中文摘要、英文摘要、关键词、章节编号、图表编号、三线表、参考文献及模板要求的标点格式均经过最终检查。
8. 全文应由三名成员共同校对，确保训练参数、数字、截图与代码产出一致。

### 9.4 过程证据的保存时点

- **数据阶段：** 来源说明、质量检查结果、类别统计、数据样例、划分清单。
- **C0 阶段：** 环境信息、训练参数、日志、最佳权重、评价指标、训练曲线。
- **C1 阶段：** 迭代动机、改动项、训练结果、与 C0 比较、真实错误案例。
- **工程阶段：** 系统结构图、关键页面截图、异常输入用例、运行复现记录。
- **交付阶段：** 三人审核记录、结论核对、最终参考文献与演示流程。

## 10. 开发阶段、三人分工与交付计划（建议 4 周）

### 10.1 阶段计划

| 周次 | 阶段目标 | 主要任务 | 阶段交付与验收 |
|---|---|---|---|
| 第 1 周 | 需求与数据定稿 | 确认需求、数据授权与来源，EDA、质量核查、固定划分，完成环境验证 | 需求文档、数据报告、split 文件；AC-01/02 |
| 第 2 周 | 完成 C0 MVP | C0 训练/评价、单图 Web、错误处理、运行说明 | C0 权重、日志、Streamlit、初版 README；AC-03～07 |
| 第 3 周 | 模型迭代与分析 | C1 微调；比较实验结果、模型错误案例；报告对应章节同步撰写 | C0/C1 结果、图表、实验记录；AC-08/09 |
| 第 4 周 | 工程验收与报告 | 复现、测试、套用论文式模板、完整报告、答辩演练；有余力再考虑扩展 | 最终代码、文档、模型、报告与演示；AC-10/11 |

若只有 3 周，优先保留 MVP、C1、实验记录与报告；取消所有 O2 内容。**目前没有明确的最终截止日期，上述为相对周次，不是确认的实际日历安排。**

### 10.2 三人团队建议分工（负责人可互换）

| 暂定角色 | 主要负责 | 共同评审/协作 | 负责提交的证据 |
|---|---|---|---|
| 成员 A：数据工程负责人 | 数据来源与许可核查、EDA、质量检查、固定划分、数据变换配置 | 与成员 B 核对增强、类别映射与泄漏风险 | 数据报告、划分清单、样本图、数据检查记录 |
| 成员 B：模型实验负责人 | C0/C1 训练、参数记录、模型权重、评价指标、误分类分析 | 与成员 A 核对输入处理；与成员 C 核对加载与推理 | 模型权重、日志、曲线、指标表、错误案例 |
| 成员 C：系统与交付负责人 | Streamlit、推理流程、输入校验、工程测试、README、演示整合 | 与成员 B 核对模型输出；联合完成实验复现 | 可运行 MVP、测试记录、工程架构、使用说明 |

**共同责任（不可完全外包给某一成员）：** 三人均参与需求确认、实验结论审核、报告撰写或校对、答辩演练。每人至少能够独立说明数据划分、迁移学习原理、模型评价指标和系统运行流程。

### 10.3 团队协作验收方式

- 第 1 周末：A 展示数据统计与划分，B/C 交叉检查；三人确认数据标签映射。
- 第 2 周末：B 展示训练与真实结果，C 演示上传预测，A 检查训练/测试数据一致性；完成 MVP 联合验收。
- 第 3 周末：三人共同评审 C0/C1 对比分析，明确结论与局限，并更新报告图表。
- 第 4 周末：由非对应模块负责人按 README 复现关键流程；三人分别准备答辩内容并互相提问。

上述为建议的职责拆分，不意味着三人各自独立开发后才做集成；跨模块接口与数据规范应先约定。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 数据镜像不一致、图片损坏或近重复 | 评价失真 | 数据来源记录、完整性检查、人工复核及固定划分 |
| 图像增强破坏缺陷语义 | 性能下降或结论不可信 | 小幅增强、示例审核、单因素比较 |
| 训练集指标很高但验证集下降 | 过拟合 | 早停、适度增强、微调范围控制并分析曲线 |
| Web 与训练预处理不同 | 推理结果异常 | 共用推理预处理逻辑，测试输入尺寸和通道 |
| 预训练权重下载/环境依赖失败 | 无法复现 | 固定依赖版本、保留权重获取方式、提前完成离线启动测试 |
| 开发延期 | 报告和验收不足 | 冻结 MVP 范围，优先 AC 项，取消批量及额外模型 |
