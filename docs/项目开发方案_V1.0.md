# 基于迁移学习的钢材表面缺陷分类与可视化分析系统
## 项目开发方案（V1.0）

> 编制日期：2026-11-08  
> 依据文档：`钢材表面缺陷分类项目_需求说明与验收标准_V0.2.md`（以下简称"需求 V0.2"）、`项目选题建议与需求确认.md`（以下简称"选题建议"）  
> 文档用途：把已确定的需求转换为可执行的开发步骤、模块接口、阶段计划和检查点  
> 方向说明：项目方向、任务边界、M0/F1/O2 优先级与验收标准沿用需求 V0.2，本方案不扩大范围。"训练样本量曲线"作为额外内容保留在第 13 章，只在核心交付完成后实施。

## 1. 开发目标与交付层级

| 层级 | 内容 | 对应验收 |
|---|---|---|
| M0：可运行 MVP | 数据核查与固定划分、C0 训练与评价、Streamlit 单图分类、异常处理、README 复现 | AC-01 ～ AC-07 |
| F1：最终课程交付 | C1 部分微调、C0/C1 对比、错误分析、测试记录、课程报告与演示 | AC-08 ～ AC-11 |
| O2：额外内容 | 训练样本量曲线（优先）、简单 CNN、随机初始化 ResNet18、增强消融等 | 不影响通过判定 |

开发顺序固定为：**环境与数据 → C0 全流程打通 → Web 页面 → C1 迭代 → 测试与报告 → 额外内容**。前一层级未通过时，不启动后一层级的新功能。

## 2. 开发原则

1. **先打通，再优化。** 第一周末尽量完成一次最简 C0 试跑，确认数据、环境和真实指标水平，再细化实验。
2. **单一配置来源。** 类别映射、预处理参数、路径和超参数都写在配置文件里，训练、评价、推理、页面共用同一份，不在代码中重复硬编码。
3. **测试集只用一次。** 验证集负责模型选择；最终方案锁定后统一运行测试集评价，不根据测试结果回头调参。
4. **所有结果可追溯。** 每次实验生成独立的运行目录，保存配置副本、日志、权重、指标和图表；报告中的数字只从这些文件中取。
5. **如实记录。** C1 未提升、训练失败、指标退化都保留记录，作为报告反思素材。

## 3. 开发环境与技术栈

| 项目 | 选择 | 说明 |
|---|---|---|
| 操作系统 | Windows | 需求 V0.2 设定；成员机器以实际为准 |
| GPU | NVIDIA RTX 4060 8GB（计划值） | 第 0 阶段核实；无 GPU 的成员可用 CPU 跑推理与页面 |
| Python | 3.11 | 使用 venv 或 conda 建立独立环境 |
| 深度学习 | PyTorch + torchvision（CUDA 版） | 从 PyTorch 官网按 CUDA 版本选择安装命令，安装后记录实际版本 |
| 其他依赖 | scikit-learn、Pillow、Matplotlib、NumPy、PyYAML、Streamlit、pytest、imagehash（近重复检查） | 版本固定写入 `requirements.txt` |
| 版本管理 | Git + GitHub 私有仓库 | 数据集与大体积权重不提交到仓库 |

环境验证脚本 `scripts/check_env.py` 输出：Python 版本、PyTorch/torchvision 版本、`torch.cuda.is_available()`、GPU 型号与显存、ResNet18 预训练权重能否加载。每位成员运行一次并把输出保存到 `docs/env/`。

预训练权重首次下载后保存在本地缓存，并在 README 中写明离线放置方法，避免演示现场因网络问题无法加载。

## 5. 配置与模块接口约定

### 5.1 公共配置（`configs/base.yaml`）

```yaml
classes: [Cr, In, Pa, PS, RS, Sc]   # 列表顺序即数字标签 0~5，任何模块不得自行遍历目录生成
class_names:
  Cr: Crazing
  In: Inclusion
  Pa: Patches
  PS: Pitted Surface
  RS: Rolled-in Scale
  Sc: Scratches
seed: 42
data:
  raw_dir: data/raw/NEU-CLS
  split_dir: data/splits
  split_ratio: [0.70, 0.15, 0.15]
preprocess:
  image_size: 224
  to_rgb: true                       # 灰度复制为 3 通道
  mean: [0.485, 0.456, 0.406]        # 与 ImageNet 权重一致
  std:  [0.229, 0.224, 0.225]
app:
  checkpoint: results/model/best.pt
  max_upload_mb: 10
```

训练时把完整配置副本写入运行目录；权重文件 `best.pt` 内同时保存 `state_dict`、`classes`、`preprocess` 和配置名称，页面加载权重时以权重内的映射为准，并与 `base.yaml` 比对，不一致时报错。

### 5.2 模块接口

| 模块 | 主要函数 | 输入 → 输出 |
|---|---|---|
| `data/split.py` | `make_splits(cfg)` | 清洗后文件列表 → `train/val/test.csv`（列：`path,label,label_id`） |
| `data/dataset.py` | `NEUDataset(csv_path, transform, classes)` | 清单 → `(tensor, label_id)` |
| `data/transforms.py` | `build_train_transform(cfg)`、`build_eval_transform(cfg)` | 配置 → torchvision 变换 |
| `models/build.py` | `build_model(num_classes, pretrained)`、`set_trainable(model, mode)` | `mode ∈ {"c0", "c1"}` 控制冻结范围 |
| `predict.py` | `load_predictor(ckpt_path)`、`predict(image: PIL.Image) -> dict` | 单图 → `{"label", "label_name", "probs": {类别: 概率}}` |
| `evaluate.py` | `evaluate(ckpt, split="val"/"test")` | 权重 + 清单 → 指标 JSON、逐类 CSV、混淆矩阵、错误样本列表 |

`predict.py` 是页面和测试的唯一推理入口，内部只调用 `build_eval_transform`，从结构上保证训练评价与页面推理预处理一致（对应需求 V0.2 第 11 章"Web 与训练预处理不同"风险）。

## 6. 数据工程实施步骤

| 步骤 | 工作 | 产出 |
|---|---|---|
| D1 获取 | 优先从 NEU 官方页面下载 NEU-CLS；官方链接失效时使用公开镜像，并注明镜像地址。区分 NEU-CLS（分类）与 NEU-DET（检测） | `docs/data_source.md`：来源、下载日期、归档文件名、SHA256、使用条件 |
| D2 核查 | `inspect.py` 统计每类数量、尺寸、通道、格式，尝试解码每张图记录损坏文件 | `docs/data_report.md` 中的统计表、类别数量图 |
| D3 去重 | 用文件 MD5 找完全重复；用感知哈希（pHash，汉明距离阈值先设 ≤4）列出疑似近重复，人工逐组复核 | 重复/近重复清单与处理结论 |
| D4 探索 | 每类抽 8 张样例拼图；计算灰度均值/标准差、绘制每类灰度直方图 | 样例图、灰度分布图 |
| D5 划分 | 对确认后的样本做分层 70/15/15 划分，种子 42；确认为近重复的图片放入同一集合 | `data/splits/*.csv` |
| D6 校验 | `verify_split.py` 检查三集合无文件交叉、各类比例、近重复组未跨集合 | 校验输出存入 `docs/` |
| D7 增强审核 | 训练增强初定：水平翻转、垂直翻转、±15° 旋转、轻微亮度对比度扰动；每类生成增强示例图，三人确认不改变缺陷语义 | 增强示例图、确认记录 |

划分清单一旦生成并提交，后续所有实验（含额外内容）都使用同一份测试集。若之后发现数据问题需要重新划分，记录原因并让所有已做实验重跑。

## 7. 模型训练实施

### 7.1 训练脚本统一行为

`train.py --config configs/c0.yaml` 执行以下流程：

1. 固定 Python、NumPy、PyTorch 随机种子，DataLoader 使用固定 `generator` 与 `worker_init_fn`。
2. 创建运行目录 `runs/<日期时间>_<配置名>_seed<种子>/`，写入配置副本和环境信息。
3. 每个 epoch 记录：训练损失、训练准确率、验证损失、验证准确率、验证 Macro-F1、学习率、耗时；写入 `history.csv`。
4. 以验证 Macro-F1 最高保存 `best.pt`，同时保存 `last.pt`；早停按验证 Macro-F1 判断。
5. 训练结束自动在**验证集**上运行评价，生成曲线与混淆矩阵。测试集评价单独执行（见第 8 章）。

Windows 下 DataLoader 多进程需要把入口代码放在 `if __name__ == "__main__":` 内；`num_workers` 先设 2，出错时改 0。

### 7.2 C0：冻结主干

| 配置 | 取值 |
|---|---|
| 模型 | `resnet18(weights=ResNet18_Weights.IMAGENET1K_V1)`，`fc` 替换为 `Linear(512, 6)` |
| 可训练参数 | 仅 `fc` |
| BatchNorm | 主干全部处于 `eval()` 模式，运行均值/方差不更新（每个 epoch 调用 `model.train()` 后需重新把主干设为 `eval()`） |
| 优化器 | Adam，lr = 1e-3 |
| Batch Size | 32（显存不足改 16 并记录） |
| Epoch | 最多 15，早停耐心 5 |

### 7.3 C1：部分微调

| 配置 | 取值 |
|---|---|
| 初始化 | 加载 C0 的 `best.pt` |
| 可训练参数 | `layer4` 与 `fc` |
| BatchNorm | `layer4` 内 BN 随训练更新，其余主干 BN 保持 `eval()`；在实验记录中写明 |
| 优化器 | Adam，lr = 1e-4（`layer4` 与 `fc` 可先用同一学习率） |
| Epoch | 最多 15，早停耐心 5 |
| 记录 | 额外训练轮数、耗时、可训练参数量，与 C0 并列 |

报告中说明：C1 相对 C0 的变化同时包含"解冻 layer4"和"额外训练预算"两个因素。若时间允许，追加一个"C0 继续冻结训练相同轮数"的对照（C0-ext），用来区分两个因素；该对照属于 O2。

### 7.4 随机种子重复

C0 和 C1 的最终配置确定后，用种子 42、43、44 各训练一次，报告均值与标准差。主模型（页面使用的权重）在实验开始前约定为种子 42 的结果，不按测试表现挑选。三个种子对 RTX 4060 的总训练成本预计较小，列入 F1 计划；若时间不足可降为单种子，并在报告中注明。

## 8. 评价流程

### 8.1 两阶段评价

| 阶段 | 使用数据 | 目的 | 规则 |
|---|---|---|---|
| 开发期 | 验证集 | 调参、选 epoch、比较 C0/C1 | 可多次运行 |
| 锁定后 | 测试集 | 最终报告指标 | 在 `docs/experiment_log.md` 写下"方案锁定"记录（日期、选用配置、权重路径）后，统一运行一次 |

### 8.2 评价输出（`evaluate.py`）

- `metrics.json`：Accuracy、Macro-Precision、Macro-Recall、Macro-F1。
- `per_class.csv`：六类 Precision / Recall / F1 / 样本数。
- `confusion_matrix.png`：计数版与按行归一化版。
- `errors.csv` 与错误案例拼图：每个误分类样本的路径、真实类别、预测类别、六类概率。
- 训练曲线：损失曲线、验证 Accuracy 与 Macro-F1 曲线。

### 8.3 错误分析

汇总测试集全部误分类样本（目标至少 5 个；不足 5 个时如实列出全部并说明），按"真实类别 → 预测类别"分组，结合图片描述可能的混淆原因（例如相似纹理、对比度低）。验证集上的错误也可作为补充素材，但需标明来源。

## 9. Streamlit 页面开发

### 9.1 页面结构

| 区域 | 内容 |
|---|---|
| 侧边栏 | 模型信息（配置名、训练日期、种子）、适用范围说明 |
| 页面 1：单图分类 | 上传 JPEG/PNG → 原图预览 → 预测类别（中英文名）→ 六类概率条形图 → 固定提示"仅支持六类已知缺陷分类，不等于质量合格判定；概率不是校准后的正确率" |
| 页面 2：实验分析 | 从 `results/metrics/` 读取并展示测试指标、逐类表格、混淆矩阵、训练曲线、C0/C1 对比、错误案例 |

页面 2 只读取评价脚本导出的文件，不在页面中重新计算或手填数字。

### 9.2 实现要点

- 用 `@st.cache_resource` 缓存 `load_predictor`，模型只加载一次；上传时只做推理，不训练。
- `st.file_uploader(type=["jpg", "jpeg", "png"])` 限制格式；后端再用 Pillow `Image.open().convert()` 解码校验，捕获异常后提示"文件无法解码"。
- 文件大小超过 `max_upload_mb` 时提示并拒绝；同时在 `.streamlit/config.toml` 设置 `maxUploadSize`。
- 权重文件不存在或类别映射不一致时，页面显示错误说明和 README 中的解决步骤，页面其余部分仍可访问。
- 推理时使用 `torch.no_grad()`，GPU 不可用时自动使用 CPU。

### 12.2 Git 协作

- `main` 分支只合并通过检查的代码；每人在功能分支开发（如 `feat/data-split`、`feat/app`），通过 Pull Request 合并，至少一名其他成员查看后合并。
- 提交到仓库的内容：代码、配置、划分清单、文档、最终图表与指标。不提交：原始数据、`runs/` 中的权重。最终权重通过网盘或 GitHub Release 共享，README 写明下载与放置位置。
- `.gitignore` 至少包含 `data/raw/`、`runs/`、`checkpoints/`、`*.pt`、`__pycache__/`、虚拟环境目录。

## 13. 额外内容：训练样本量曲线（O2，保留待做）

### 13.1 启动条件

同时满足以下条件才启动：AC-01 ～ AC-09 已通过；报告 II～IV 章已有初稿；距截止日期仍有至少一周。

### 13.2 研究问题

在训练样本较少时，冻结主干（C0）与部分微调（C1）的分类表现和稳定性有何差异？

### 13.3 实验设计

| 项目 | 设置 |
|---|---|
| 训练子集 | 从已固定的训练集中，每类分别抽取 10 / 20 / 50 / 100 / 210 张；采用嵌套抽样（小子集包含于大子集），每个规模保存清单 |
| 验证集、测试集 | 与主实验完全相同，不做缩减 |
| 方案 | C0 与 C1，训练配置与主实验一致 |
| 重复 | 每个规模至少 3 个抽样种子 |
| 输出 | 横轴为每类训练样本数、纵轴为 Macro-F1（均值 ± 标准差）的曲线；小样本下的混淆矩阵与错误案例 |

总训练次数约为 5 个规模 × 2 个方案 × 3 个种子 = 30 次。实际耗时以第 2 周 C0 正式训练的单次耗时估算后再决定规模数量。时间不够时优先做 10 / 50 / 210 三档。

### 13.4 与主线的关系

- 不修改主实验的划分、配置和验收结论。
- 代码只新增 `src/data/subset.py` 和一个循环调用 `train.py` 的脚本，复用现有模块。
- 结果作为报告第 IV 章的补充小节或附录；若未完成，只在"展望"中说明。

## 14. 风险与应对（开发层面）

| 风险 | 触发信号 | 应对 |
|---|---|---|
| 官方数据链接失效 | 第 0 阶段无法下载 | 使用公开镜像，核对每类 300 张与文件名格式，记录来源 |
| CUDA 版 PyTorch 安装失败 | `torch.cuda.is_available()` 为 False | 按显卡驱动版本重选安装命令；最差情况用 CPU 训练 C0（数据量小，可完成） |
| 成员代码风格与接口不一致 | 合并冲突、预处理重复实现 | 第 0 阶段先合并空接口与配置；推理统一走 `predict.py` |
| C0 指标已接近满分，C1 差异很小 | 验证集错误数个位数 | 用多种子均值与标准差描述差异，不夸大小幅变化；在报告中说明数据集难度，额外内容可作补充 |
| C1 过拟合 | 训练损失持续下降、验证损失回升 | 依靠早停；必要时降低学习率到 5e-5，记录调整过程 |
| 演示环境出问题 | 现场无法加载模型 | 演示前一天在演示电脑上离线完整走一遍；准备录屏备份 |
